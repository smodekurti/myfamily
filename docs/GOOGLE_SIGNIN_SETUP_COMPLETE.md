### Flutter Code (`lib/app/data/repositories/auth_repository.dart`)
```dart
// Native Google Sign-In implementation
Future<AuthResponse?> signInWithGoogle() async {
  try {
    // Sign in with Google using native SDK
    final googleUser = await _googleSignIn.signIn();
    
    if (googleUser == null) {
      return null; // User cancelled
    }
    
    // Get authentication tokens
    final googleAuth = await googleUser.authentication;
    
    // Authenticate with Supabase using ID token only
    final response = await _supabase.auth.signInWithIdToken(
      provider: OAuthProvider.google,
      idToken: googleAuth.idToken!,
      // Note: accessToken removed to avoid nonce issues
    );
    
    if (response.user != null) {
      await _createOrUpdateUserProfile(response.user!);
    }
    
    return response;
  } catch (e, stackTrace) {
    _logger.e('Google Sign-In Failed: $e');
    _logger.e('Stack trace: $stackTrace');
    rethrow;
  }
}
```

## 📝 Notes

### Why "Skip nonce checks" is Required

**Native mobile OAuth (iOS/Android) vs Web OAuth:**
- **Web OAuth**: Nonces are generated by the server and validated end-to-end
- **Native mobile OAuth**: The native SDKs handle authentication differently, and custom nonce injection isn't supported by the Google Sign-In SDK

**Security Considerations:**
- Enabling "Skip nonce checks" is the **standard approach** for native mobile Google Sign-In with Supabase
- The ID token is still cryptographically signed by Google and validated by Supabase
- The "audience" (client ID) is still validated against your authorized client IDs
- This is a widely accepted pattern for native mobile OAuth flows

**Alternative (if you need nonce validation):**
- Use web-based OAuth flow instead of native sign-in
- Requires different implementation (OAuth redirect flow)
- More complex UX (browser-based sign-in instead of native sheet)

### Android Setup

- For Android, create an Android OAuth client in Google Cloud Console
- Use SHA-1 certificate fingerprint for Android client
- Add Android client ID to Supabase authorized client IDs
- Update `android/app/src/main/AndroidManifest.xml` with proper intent filters
- "Skip nonce checks" will work for Android as well
